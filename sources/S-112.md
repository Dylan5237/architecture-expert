# Electron Process Model — Desktop 正向权威来源

## 核心主张
- 多进程模型：main 进程（Node.js，单一入口、应用生命周期所有者）/ renderer 进程（Chromium 隔离实例，无 Node.js 默认权限）/ utility 进程。
- contextIsolation + preload contextBridge：渲染进程经显式最小 IPC 面访问特权能力——capability 模式的桌面形态。
- 继承 Chromium 多进程架构：进程隔离即故障与安全边界。

## 架构价值
- Desktop 形态下 H2a（边界）/H3（有界执行）/H10（信任最小化）的直接例证：渲染进程崩溃不致命、特权集中在 main、IPC 面最小化。

## 争议/误用
- 厂商文档：对平台契约 normative；不得推导「桌面应用都应该多进程」的通用结论。
