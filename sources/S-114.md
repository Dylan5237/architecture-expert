# Armstrong 2003 — Erlang/OTP 可靠性奠基论文

## 核心主张（修正版）
- 错误恢复范式：let-it-crash = 「让另一个进程修错」；supervision tree 是层级化的错误处理归属模式。
- **限定**：OTP supervision 是 supervised tree 的 pattern/semantics——是合规的 ownership 机制实例，**不是对每个 Erlang process 的普适 runtime invariant**；不得写「每个 Erlang process 都有 supervisor」或「runtime 禁止 unsupervised spawn」。
- restart intensity 为显式逃逸阀。

## Stage 5 改变的结果
- P-001 攻击 1：supervised tree 证明「显式所有权可编码进架构且生产验证」——P-001 的最强潜在反例不成立；但它证明的是「supervision 是合规机制」，不是「无 supervision 的 spawn 不存在」。
- P-001 GOOD CASE：supervised daemon 的「无限运行」由 supervision + restart intensity 兜底。

## 备注
- 先前引用的 Akka.NET「actors cannot be orphaned」泛化已从证据中移除（不作为本来源主张）。
- OTP 显式管理生命周期所有权，不覆盖数据/状态所有权（ETS、registered name）——P-001 收窄时注明。
