# Clean Architecture — 教条风险来源（登记意见）

## 核心主张
- 依赖规则：同心圆层，源码依赖只指向内层；业务规则在中心，框架/DB/UI 是外围细节。
- 综合 Hexagonal/Onion/Screaming 为统一模型；好架构推迟决策。

## 争议/误用
- 业界广泛批评教条化与样板代码膨胀；层数与「纯净度」缺乏实证收益数据。
- 在本项目中：研究其机制（依赖方向保护什么），绝不直接接受其结论。任何 Clean Architecture 派生主张默认 CONTEXT_DEPENDENT。
