# Arrakis（OSDI 2014）

## 核心主张（修正版，维度特定）
- 传统内核中介 I/O 是为「强制进程隔离」；Arrakis 让应用直接访问虚拟化设备、多数 I/O 跳过内核，获 2–5× 延迟、9× 吞吐改善。
- **本条仅证明：在 hardware-virtualized I/O 上，device/network/disk 的保护可由内核控制面 + SR-IOV/IOMMU 硬件机制执行**——隔离在该 I/O 保护维度上从进程边界下放硬件。
- **不得泛化为「硬件机制替代所有维度的故障遏制」**。

## Stage 5 改变的结果
- P-004 收窄：隔离单元的粒度是替代性保证机制（进程边界/硬件虚拟化等）与成本模型的函数，不默认进程边界——但该结论限于此 I/O 保护维度的证据强度。
