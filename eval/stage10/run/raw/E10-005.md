## Decision summary

**Do not merge as-is.** The rename is a breaking change to a public contract consumed by ~1400 independent external integrators, shipped with no compatibility direction, no migration path, and no deprecation notice — violating both MP-007 (FP-008 mechanism) and the accepted product contract (ToS: 6-month deprecation notice). Green CI proves only that the *internal* consumer was updated; external consumers are by definition not in your CI. The minimum safe fix is small: keep the public payload in snake_case and confine camelCase to internal surfaces.

## Key reasoning

- **S4 / GOOD CASE gate** — checked qualifiers, not titles:
  - GC-009 (governed break): requires a higher-priority **security/correctness** requirement. An internal style guide is neither; cosmetic uniformity is not a governing priority. Not applicable.
  - GC-010 (governed ecosystem migration): requires coordinated migration governance. History shows no deprecation mechanism has ever been used; the PR ships the break directly. Not applicable.
  - GC-011 (internal churn is legal): the *internal consumer* update is internal churn — fine. The *public payload schema* is not internal; it is the documented stable external contract. Not applicable to the payload rename.
  - GC-007: the wide-but-coherent diff (producer + consumer + lint) is **not** flagged as a locality violation; spread is a review signal only, and here the spread is coherent. The defect is the missing direction/notice, not the diff size.
- **Lint rule is newly load-bearing**: as written it will re-forbid snake_case in the public schema, guaranteeing recurrence of this same break. The min fix must scope the lint to exclude the public payload contract.
- **Not ARCH_CONFLICT**: no genuine capability-vs-constraint impasse — the local fix protects the contract while still serving the style guide internally. AX-002 is violated by the PR as written (silent contract shrink for implementation/style convenience), remedied by the blocker + min fix, not by a conflict record.
