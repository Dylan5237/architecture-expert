## Decision rationale

**The PR's fix streams the wrong thing.** The OOM happens during graph *build* (RUNTIME: 4GB heap exhausted, 11 min in, 40k modules); streaming the *output* cannot bound a working set that is fully materialized before any output exists. The `--max-memory` flag raises the heap cap but does not bound the dimension that grows — footprint scales with module count (~155KB/module measured), so the flag only relocates the crash threshold to wherever each user sets it. That is FP-003 (unbounded per-work memory dimension) defeating the accepted scaling target (PRODUCT_INTENT: works up to 100k modules in CI).

- 40k modules → 6.2GB resident (CODE, measured), OOM at default CI heap (RUNTIME). The target is 100k; linear extrapolation ≈15GB+ (HYPOTHESIS, but the blocker does not rest on it — 40k already fails below target).
- "Entire graph in memory 'for correctness'" conflates *needs a whole-graph view* with *needs whole-graph residency*. Two-pass / sequential / compact external representations are the standard single-process shape for exactly this scale. That claim is unverified (USER_ASSERTION in the PR, HYPOTHESIS).
- D-04 check (Q-025): this is a **bound** problem (MP-003/FP-003), not a missing overload policy (MP-009) — one batch job whose per-work footprint grows with external input, not arrival rate vs capacity. No admission/backpressure machinery is warranted.
- GC check: GC-002 does not save the delta — its qualifier says GC exempts *reclamation only* and the aggregate budget must remain compatible with required capacity; a user-raised hard cap on an input-scaling footprint leaves the dimension unbounded. GC-004 is inapplicable (finite job, not indefinite lifetime).

**Minimum correction to this PR** (no infra, no redesign — respects the single-process Node constraint, AX-004):

1. Bound the resident working set in `ImportGraphBuilder`: parse modules one at a time; persist the edge set to a compact sequential/on-disk representation; run the analysis as bounded-memory passes over it. If some specific output genuinely needs whole-graph residency, that is the discriminating evidence to produce (finding 2) — and then the choice is external-memory representation vs. raising the documented hardware floor, the latter being an AX-002 product-contract change for the owner, not a flag.
2. Keep `--max-memory` only as an escape hatch, not as the fix; it cannot carry the property.
3. Add a synthetic ≥100k-module fixture with a memory-ceiling assertion so CI enforces the bound instead of user tuning (current tests stop at 5k — coverage gap below target).
