## 1. What actually happened (failure propagation)

The timeline and code/config evidence chain into one mechanism pair:

**Trigger — synchronized expiry (CONFIG).** Uniform 60 s TTL with no jitter means cached copies of the hot article expire in the same instant, and re-expire in sync on every cycle. The arrival spike at the DB is not smoothed by anything.

**Amplifier 1 — miss fan-in (CODE).** Cache-aside with no request coalescing: on a miss, *every* in-flight request issues its own DB query. Concurrent DB load for the hot key scales with request concurrency (~10⁵), not with the number of distinct keys (1). This is an unbounded per-key concurrency dimension on a shared resource (FP-003 bound side / MP-003), landing on a path with no governed capacity boundary at all (FP-010 / MP-009). Result, confirmed by RUNTIME: 500/500 connections within 800 ms.

**Amplifier 2 — no propagation cut (CODE).** The 500-connection pool is shared by *all* article queries with no per-key/class/tenant budget. Once the hot key's misses occupy the pool, the failure domain is structurally "everything behind the pool": FP-004 shared-resource cascade. Blast radius (all articles, p99 8 s+ for 4 min — RUNTIME) ≫ intended domain (the hot article).

**Sustaining loop.** Pool saturation → query latency 30× → each miss handler holds its connection longer (L = λW: occupancy explodes when W jumps under fixed capacity) → other keys' expired entries cannot repopulate → service-wide cache hit ratio drops → even more misses → recovery only after the hot entry finally reloads (~4 min). The degradation you suffered is *accidental and ungoverned*; nothing on the path decides to admit, refuse, or degrade.

**Possible third amplifier — unconfirmed.** Nothing in the evidence says whether clients/mesh retried on the 8 s latencies. If they did, FP-011 (retry amplification) contributed; the evidence neither confirms nor excludes it. This does not change fix ordering (below), but it changes whether a retry budget belongs in the fix set.

## 2. What to fix first

**Fix 1 (breaks the observed mechanism, smallest change):**
- **Per-key request coalescing (single-flight) at the miss handler** — one in-flight DB load per key; concurrent misses await the shared completion. A concrete instance of T-004 bounded concurrency; naming it as technique, not as a universal tactic. Code-local.
- **TTL jitter** (e.g., 60 s ± bounded random) — desynchronizes expiry, removing the synchronized arrival spike. Config-local.

These two alone convert miss concurrency from ~N to ~1 per key and would have prevented this incident as observed.

**Fix 2 (contains propagation — protects "other articles stay fast" even when the trigger differs):** cut the shared-pool coupling: per-class connection budget (reserved sub-pool for non-miss-path queries) or a global cap on miss-path concurrency. T-004/T-006; placement may be service, gateway, or mesh (GC-015) — service-local code is not required.

**Fix 3 (residual, only if demonstrated):** if distinct-key miss waves (front-page churn) can still exceed DB capacity, the path needs a governed overload *policy* — bounded serve-stale (degradation, T-009) or shedding (T-008). Note AX-002: serving stale past TTL is a freshness-contract change; if adopted, the staleness bound is an explicit owner/product decision, not a silent one.

**Not the fix:** horizontal DB scaling (slow to provision per your constraint, and it treats the symptom — the mechanism re-arms at higher N) or any rewrite/microservice split (AX-004: local fixes protect the named properties here).

## 3. Open evidence (cheap, named)

1. **Cache/pool deployment shape:** shared cache vs per-instance caches, and pool per-instance vs total — decides whether in-process single-flight suffices or cross-instance coordination (lock/lease) is needed. One config/infra check.
2. **Retry behavior in the incident window:** per-path retry rate + client timeout/retry config → adjudicates FP-011 in or out of the fix set (Q-006).
3. **Load replay after Fix 1+2:** per-key miss-query count ≈ 1 and pool occupancy with margin under a replayed spike → discharges Finding 2.
