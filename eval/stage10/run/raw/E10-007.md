## E10-007 — Incident attribution and minimum correction

**Route (AUTO)**

`route: {mode: INCIDENT_ANALYSIS, dp: DP-005, overlays: [runtime/concurrency, failure/reliability, resource/per-work-bounds], basis: object is an observed production failure (valve-command deadline miss) on an existing controller, so DP-005 attributes the mechanism and names the smallest correction; overlays justified by priority inversion (concurrency), a safety path sharing heap+UART lock with telemetry (reliability), and malloc-per-iteration (resources).}`

### What the architecture contribution is

The safety-critical control path and the best-effort telemetry path share **two bottlenecks**: a single heap arena and a global UART lock. The control task (priority 9) mallocs every iteration and logs over the same UART lock telemetry holds during bursts. When telemetry (priority 2) holds either lock, the control task **blocks behind a lower-priority task** — priority inversion. "Control is highest priority, therefore it runs on time" is an *assumed* guarantee, not one the model provides under blocking locks (MP-010 / FP-012). The structural contribution is the missing failure-domain cut between the safety path and the bursty non-safety path (MP-004 / FP-004), and the unbounded/non-deterministic per-iteration `malloc` in the loop is an independent hard-real-time defect (MP-003 / FP-003).

**"Bigger CPU" is not a correction.** It shrinks the *probability* of a miss but does not bound priority inversion or allocator non-determinism — the miss remains load-shape dependent. For a safety-rated hard 10 ms deadline (AX-003 applicable), a probabilistic mitigation does not protect the property.

### Smallest fix

1. **Remove the heap from the control loop** — preallocate packet structs (static pool). Breaks the per-iteration `malloc` and the heap-lock acquisition on the critical path.
2. **Cut the shared bottlenecks (T-010, scoped)** — give telemetry its own memory pool and a **bounded, non-blocking** UART ring buffer that drops telemetry logs when full (shedding on the non-safety path only). The control path then never waits on a lock telemetry can hold.
3. Only if a shared lock *must* remain on the critical path, make it a priority-inheritance mutex — but the preferred fix removes the shared locking entirely, which is both smaller and deterministic.

This is local (two resource-boundary changes), not a redesign; no CAN hardware change is required.
