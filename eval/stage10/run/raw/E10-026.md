## S5 — Findings

**F1. `HIGH_CONFIDENCE_RISK` — unbounded tombstone retention in long-lived boards.**
- Property: resource budget / sync cost of long-lived boards (the only part of the review with a real mechanism).
- Mechanism: deletions leave tombstones; no compaction; state grows linearly with edit history (FP-003 retention/memory dimension; T-004).
- Failure mode: eventually board state exceeds any memory/sync budget; metadata already 3.8x payload at 3 years.
- Impact: material only asymptotically — no budget violated *today* on record → not a BLOCKER.
- **refutation_or_invalidation:** (a) realistic worst-case board age/size shown to fit memory + sync-latency budgets with margin; or (b) compaction exists in code not visible here.
- **Min correction:** bounded tombstone retention via causally-safe compaction (e.g., per-board version-vector watermark; compact tombstones below the watermark, offline stragglers resync from snapshot) — a concrete technique under T-004's bounded-occupancy intent, not a new canonical node — plus define a per-board metadata budget/SLO so the risk is measurable. Compare to redesign: replacing the CRDT is strictly wider, does not follow from the mechanism, and sacrifices a protected property.
