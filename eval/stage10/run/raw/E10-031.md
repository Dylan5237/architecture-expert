**S3 — Mechanism.** Capacity cut of 60% on the checkout path's shared bottleneck, with an unbounded queue in front of it (FP-003 / L=λW, MP-003): if peak concurrent DB demand exceeds 200, arrivals convert to backlog; per-work wait grows; with request deadlines this becomes checkout failures, without them it becomes latency collapse — either branch harms the property. Q-025 discrimination: this is a bound/capacity question (MP-003), not primarily a missing-overload-policy question (MP-009, D-04) — though the min correction's queue element is an MP-009 *placement* choice.

**S4 — GC gate before defect.** GC-004: not applicable — the issue is not lifetime confusion. GC-002: a pool cap is a legal bound form, so "the pool has a smaller number" is not itself a violation — the defect is the unsupported capacity cut plus observed harm; GC does not exculpate. GC-015: path-level admission would count as governed capacity if it existed — no evidence it does; and whatever exists did not protect the property at 200. Cheapest discriminating evidence (Q-006): pool utilization / connection-acquire wait for 10:20–11:00, if retained.

**S5 — Adjudication.** Merge-as-is is a MUST_FIX on the delta: the only production trial of this exact delta correlates with a material success-rate drop with tight temporal coupling and a specific plausible mechanism, and the delta carries no demand-side evidence (no load test >1x). Causation stays HYPOTHESIS, so the review does not rest on it alone — an unmeasured 60% capacity cut is unmergeable regardless. The cost goal stays alive via the minimum correction, not by rejection.

**S6 — Stop.** Min correction to the delta is clear → stop rule 2.
