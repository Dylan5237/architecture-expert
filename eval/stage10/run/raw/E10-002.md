`route: {mode: ARCH_REVIEW, dp: DP-002, overlays: overload (primary) + resources (secondary), basis: object is the existing checkout path judged as-is after recurring incidents; symptom shape is a retry storm against an ungoverned overload path, and the unbounded gateway queue is an unbounded per-work count/size, which pulls in the resources overlay per the index discriminator.}`

## Decision rationale

The proposed fix — migrating checkout to standalone microservices — does not break the failure mechanism and is not required here. The mechanism is a retry-amplified overload collapse at the *path* level: an unbounded gateway queue with no admission/shedding (FP-010), compounded by a client SDK that retries 3× with fixed 0 ms delay and no jitter (FP-011). Both failure modes live at the gateway + client contract, which is exactly where the accepted ADR-0031 said traffic shaping belongs. Splitting the monolith would add a network hop and more timeout/retry surface, and it would contradict ADR-0031 (requiring board sign-off) without addressing either mechanism.

The minimum correction is (1) a governed gateway boundary on the checkout path — bounded queue (set `max-length`) plus admission/rejection (T-006/T-008), consistent with GC-015 and ADR-0031 — and (2) bounded, jittered, backoff-growing client retries (T-005). One open question remains: checkout is a payment mutation, and retry-on-timeout without evidence of idempotency risks duplicate charges (retry ≠ idempotency).
