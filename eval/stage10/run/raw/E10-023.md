## Review result — E10-023

`route: {mode: ARCH_REVIEW, dp: DP-002, overlays: runtime/concurrency (stale async), basis: object is an existing cross-service call path judged as-is; the symptom is caller-abandoned work that completes late and mutates state (deadline/cancellation family)}`

### What must stay true, and what actually happens

**Required property** (PRODUCT_INTENT, accepted, CONFIRMED): *cancelled orders must not hold stock.*
**Real constraint** (accepted, CONFIRMED): 500 ms per-call deadline (page responsiveness); backend gRPC, order → inventory. AX-003: no named non-negotiable applies.

Current behavior (CODE + RUNTIME, CONFIRMED): deadline fires → order service **abandons** the call, marks the order CANCELLED, emits a cancellation event; inventory has **no cancellation handler**, commits the reservation anyway (local transaction), and there is **no compensating action** on cancellation. Runtime confirms the resulting failure weekly (~130 orders; manual support release).

**KNOWLEDGE_DRIFT** (trigger 1 — observed behavior vs accepted PRODUCT_INTENT): current behavior violates the accepted property. Not contested; the drift direction is unambiguous — behavior must move toward intent.

### Mechanism (two distinct mechanisms, D-02 — not collapsed)

1. **FP-012 / MP-010 — assumed-vs-provided guarantee.** The order service's deadline path implicitly assumes *deadline exceeded ⇒ downstream work aborted*. gRPC deadline/cancellation is **cooperative**: the server must observe the context; InventoryService never does (CODE). "Client abandons" ≠ "server aborts." The assumed guarantee is not provided by the model as used. T-002 is explicit: deadline ≠ ownership (D-07).
2. **FP-001 / MP-001 — unowned cleanup of the side effect.** Once abandoned-or-committed, the reservation side effect has **no owner for stop/cleanup**: nothing consumes the already-emitted cancellation event, no reconciliation sweep exists. Cleanup has drifted into an unowned manual process (support).

Mechanism 1 creates the race; mechanism 2 is why the race's outcome persists unboundedly. The property violation is carried by mechanism 2 — which is also where the minimum correction lands.

**GC gate (S4):** GC-001 checked — not applicable (nothing supervises/owns this work; indefinite lifetime isn't the issue). GC-016 checked — not applicable (gRPC *does* offer deadline-propagation primitives; the code simply doesn't observe them — this is not punishing an implicit-but-real guarantee). No GOOD CASE rescues this path.

### Decision: not ARCH_CONFLICT

Q-010: 500 ms deadline **and** no-held-stock are not fundamentally incompatible — keep the deadline, add owned compensation. Only if product demanded *zero-latency* release at cancel would a real capability/constraint conflict (and a V-010-suffixed consistency requirement) arise. So AX-002 is honored by fixing the implementation, not by weakening either contract. Do **not** fix by raising the deadline (violates the stated constraint) or by waiting for inventory confirmation (same violation).

### Minimum correction

Property → mechanism → smallest change that breaks it:

1. **Give the reservation side effect a cleanup owner (the fix).** Inventory consumes the **existing** order-cancelled event and releases reservations for cancelled orders — idempotent release keyed by order id, plus handling for the interleavings the race guarantees: cancellation arriving *before* the reservation commits (persist a cancellation marker; refuse-or-immediately-release on insert/post-commit) and re-delivery (release must be idempotent — retry ≠ idempotency, so the release contract states its effect semantics explicitly). A periodic reconciliation sweep of reservations whose order is not active is the same mechanism in polling form and covers lost events. This is bounded, converges regardless of commit timing, and replaces the manual process with an owned lifecycle step.
2. **(Narrowing, not correctness) Server-side cancellation observation.** InventoryService checks the gRPC context before commit and aborts if already cancelled (T-002, RPC-propagation sense). Reduces late commits and wasted DB writes, but cancellation can still race the commit — per MP-010 honesty it must **not** be relied on as the guarantee. The compensator is the guarantee; this is waste reduction.

No wider redesign (no saga framework, no distributed transaction, no event sourcing) — the local fix protects the property; rejected per Q-049.
