## Decision

**Do not move SQLite writes to a background service process.** The freeze is not fixed by a process boundary; it is an unbounded per-work time/memory failure on the UI thread (FP-003). The minimum correction is an **in-process background worker** with bounded, streamed work and proper cancellation/marshaling. Separately, the "edits never lost on force-kill" requirement is already violated by the current design and the proposed process change does not fix it — that needs durable persistence of edits.
