`id`: E10-007
`title`: Embedded controller misses valve deadlines
`task_object`: observed failure on industrial embedded controller
`requested_mode`: AUTO
`user_request`: Our pressure-regulation controller occasionally misses its 10ms control deadline: the valve actuator command arrives 3-18ms late, causing pressure oscillation. Marketing wants us to 'just add a bigger CPU'. Engineering suspects the recently added telemetry block. Find the architectural contribution and the smallest fix.
`project_evidence`:
  `runtime`: "Deadline misses correlate with telemetry bursts: 200ms spikes on the CAN bus log path, allocated dynamically (malloc) inside the control loop, logging to a shared UART buffer without flow control."
  `code`: "Control loop is a fixed-priority task (highest). Telemetry was added as a lower-priority task but allocates from the same heap and takes a global UART lock; the loop also mallocs per iteration for packet structs."
  `config`: "RTOS priorities: control=9 (highest), telemetry=2; heap: single shared arena, no partition."
`constraints`:
  - industrial embedded RTOS, ARM Cortex-M, 128KB RAM
  - control deadline 10ms is a hard requirement (safety-rated)
  - no option to change the CAN sensor hardware this year
`notes_for_runner`: Fresh context.
