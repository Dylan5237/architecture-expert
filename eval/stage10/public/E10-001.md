`id`: E10-001
`title`: Desktop app freezes during file export
`task_object`: existing desktop application, as-is review of the export flow
`requested_mode`: AUTO
`user_request`: Our photo catalog desktop app (single process, local SQLite storage) freezes for 10-40 seconds when the user exports a large album. The UI is unresponsive and Windows marks it 'Not Responding'. Users kill the process and we lose their in-memory edits. We have a fix proposal but want the architecture reviewed first: should we move SQLite writes to a background service process?
`project_evidence`:
  `product_intent`: "Export must not block the UI; user edits are never lost on force-kill." (accepted requirement, v2.1 release notes)
  `code`: "ExportViewModel.Export() runs on the UI thread: queries SQLite (whole-album SELECT), writes JPEGs to disk, then updates the observable collection. There is no Task.Run or background worker anywhere in the export path."
  `test`: "Existing test exports 50 photos in-process and asserts file count; never exercises UI thread or cancellation."
  `runtime`: "Field traces: UI thread busy 10-40s; main thread performing file I/O during export; heap grows with album size."
`constraints`:
  - single-process desktop app, Windows, WPF-style UI framework
  - team of 4; no ops team; no ability to run background services on user machines beyond the app itself
`notes_for_runner`: Fresh context; provide repository access.
