## Decision rationale

**Protected property (S1).** Accepted build contract (PRODUCT_INTENT): a cached result may be reused **only when all declared inputs that affect the output are equal**; SDK headers and loaded plugins are declared inputs; conservatively declining a hit is explicitly allowed. Constraint: a slower correct build is an acceptable fallback; wrong-input reuse is not.

**Evidence baseline (S2).** Key currently = source digest + flags; patch adds compiler-executable digest; SDK header paths (environment-selected, independent of compiler installation — CONFIG) and plugin search paths (configurable — CONFIG) are **not** added to the key. TEST fixture is decisive: compiler bytes, sources, flags held fixed; declared SDK header contents changed → different executable bytes; the patched key **reuses the first executable**. The maintainer's assumption "equal compiler bytes ⇒ equal SDK/plugin inputs in every environment" is USER_ASSERTION, never promoted — and directly contradicted by CONFIG (SDK selected independently) and ARCHITECTURE_INTENT (separate release schedules for compiler, SDK, plugins).

**Mechanism (S3/S4).** FP-009: the cache layer serves an undeclared consistency (cache sense, V-010) relative to its source of truth. Key equality is a strict **subset** of declared-input equality, so key-hit ⇒ reuse fires while declared inputs differ. GC gate: GC-013 (declared merge) and GC-014 (defined append/derivation semantics) qualifiers do not apply — the reuse path has no defined derivation-equality rule for SDK/plugin inputs, and the TEST demonstrates the artifact served is inconsistent with declared inputs. No GC rescues the delta; the discriminating experiment already exists (the fixture).

**Adjudication (S5).** BLOCKER on the delta: silent wrong-input reuse, demonstrated, material to the tool's core correctness contract, no GC applicable. Minimum correction is local to this patch: complete the key's input coverage — add resolved SDK header digests (or environment-selected SDK directory identity + content digest) and resolved loaded-plugin digests to the key; **where the tool cannot enumerate the loaded plugin set (currently unevidenced), take the product-intent-sanctioned fallback: conservatively decline the hit** rather than guess. ARCHITECTURE_INTENT already authorizes exactly this ("record resolved input digests or conservatively decline a hit"), so no contract change is needed. A wider redesign (full dependency-tracing framework) is unnecessary — the local fix protects the property (AX-004).

**Drift.** Patched behavior (hit on unequal declared inputs) conflicts with accepted PRODUCT_INTENT → KNOWLEDGE_DRIFT recorded below. The maintainer's equal-bytes assumption is bare USER_ASSERTION vs project evidence — verification, not drift; it is refuted.

**Stop (S6).** Defect identified + minimum correction expressible as a change to this PR → stop rule 2. No escalation: choosing between "record digests" vs "conservative miss" is routine mechanism selection with sufficient evidence; both protect the property. (Only if owners instead proposed dropping SDK/plugins from *declared inputs* would AX-002 escalation apply — not the current ask.)
