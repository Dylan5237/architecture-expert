## Decision rationale

**Broken property (Q-001/Q-003).** Accepted exchange contract: every published length is in metres, the unit tag must truthfully describe the number, and unconverted values must not be published as metres. The recipient is an independent consumer; the convention is fixed for this review, so the correction may not "fix" this by renegotiating the tag (AX-002).

**What is actually true (Q-004/Q-005/Q-007).**

| Claim | Origin | claim_epistemic_state |
|---|---|---|
| `publish` emits `unit: "metre"` unconditionally after `normalise(raw, profile)` | CODE | CONFIRMED |
| Legacy profile is a no-op conversion (returns input number **and input unit**); current profile converts to metres | CODE | CONFIRMED |
| Reproducer: yard fixture → legacy profile → number unchanged, tag `metre` | TEST | CONFIRMED |
| Exchange test expects conversion before the metre tag | TEST | CONFIRMED |
| Affected production output retained, but carries no source-unit declaration, selected profile, input identity, or adapter build identity | RUNTIME | CONFIRMED |
| Vendor-adapter update and profile-selection config change both released in the period; no per-output mapping to either revision | HISTORY | CONFIRMED |
| "This parcel was caused by the vendor update" | USER_ASSERTION | HYPOTHESIS (ungrounded; not drift — bare assertion vs project evidence is verification, per DP-005) |

**Mechanism (S3–S4, competing candidates).** The reproducer pins the defect class: the unit tag is emitted as a constant while the *actual* unit of `normalise()`'s output varies by profile. That is an ungoverned contract break at an independent-consumer boundary (FP-008 causal account: the contract is the stable collaboration point; tag/value decoupling transfers wrong data to every uncoordinated reader). Structurally it is a variation axis (conversion policy) whose co-varying obligation (tag truthfulness) is hidden behind an unconditional literal — MP-002 framing, but it does not change the correction, so no third domain loaded.

GC gate: GC-009 (no higher-priority governed override — the convention is explicitly fixed), GC-010 (no coordinated migration), GC-011 (this is the external exchange, not tightly coordinated internals) — none apply. The cheapest discriminating evidence for the *defect* already exists: the reproducer proves the legacy path publishes prohibited output regardless of which release selected it.

**Attribution: no, it cannot already be attributed.** Two (arguably three) causal chains remain live and the retained evidence cannot separate them:

- **A — profile-selection change** selected the legacy profile → unconverted value + hardcoded tag. Matches the reproducer exactly (TEST-reproduced mechanism).
- **B — vendor-adapter update** altered source-unit handling/declaration so even the converting profile emitted a wrong scale. Consistent with an implausible length; not reproduced.
- **C — pre-existing defect**, predating both releases, needing only a trigger (a non-metre input reaching the legacy path), which either release could have supplied.

The incident note's vendor attribution is therefore not merely unproven — the only *reproduced* mechanism points at least as strongly at the profile-selection path. Per DP-005, that USER_ASSERTION stays `HYPOTHESIS` until RUNTIME/CODE ground it.

**Bounded correction (Q-046/Q-049).** Property → tag/value truthfulness; mechanism → tag emission decoupled from actual conversion; smallest change that breaks it, at the emission boundary the producer already owns:

1. Derive the tag from the normalisation result (`unit: value.unit`), not a literal; and
2. Gate at the emission boundary: refuse the work item (fail, do not publish) when the normalised unit ≠ contract unit.
3. Pin it: extend the exchange test to the legacy profile with a non-metre fixture (the reproducer shows that expectation is evidently not enforced on that path).

This is narrower than per-profile patches (which would re-couple the tag per profile and leave the next profile free to re-break it), and far narrower than schema or recipient renegotiation. **Honest residual:** the gate guarantees tag/value coupling given a truthful unit declaration from the profile/adapter; it cannot detect an upstream adapter that *mislabels* a source unit as metres. That residual is precisely what the attribution evidence below would probe — one more reason the vendor chain is not closed.

Widening is not justified: the local gate protects the fixed contract for the whole variation axis.

**Evidence placement (FP-007, Q-037/Q-038).** Two same-window releases plus an attribution question that mattered, and no output carries source-unit, profile, input identity, or build identity — attribution was designed out, and the failure mode ("unattributable incident") actually occurred. This is not a telemetry-stack complaint; four named fields for one named question. Bounded fix: stamp outputs (or a retained side-ledger keyed by output id) with profile id, adapter build id, source-unit declaration, and input reference.

**Out of scope (Q-009):** wider export-pipeline redesign, vendor-adapter review beyond this attribution, the duration histogram (no bearing on a scale error).
