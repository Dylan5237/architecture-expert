## Mechanism

The cache key is the tool's **equality oracle** for declared inputs. The patch widens the oracle along one axis (compiler bytes) while the output demonstrably depends on two more declared axes whose selection is **independent of the compiler binary** (env-selected SDK dir; configurable plugin search path). Equal key → tool declares inputs equal → reuse; but actual declared inputs differ → wrong-input reuse. The maintainer's premise fails structurally, not incidentally: independent selection mechanisms (CONFIG) and independent release schedules (ARCHITECTURE_INTENT) guarantee the compiler digest does not subsume those inputs; TEST demonstrates the divergence end-to-end.

GOOD CASE check: no GC qualifier applies — nothing accepts an incomplete reuse oracle, and the contract itself declares the conservative-miss escape hatch, so no governed exception covers this delta.

## Findings

**F1 — BLOCKER / MUST_FIX (applies to the delta).**
The patched key grants cache hits when declared inputs differ, violating the accepted build contract. Evidence: TEST (wrong executable produced on a hit), CODE (omitted input axes), CONFIG (independent selection), PRODUCT_INTENT. Impact: silent, deterministic output corruption — precisely the failure class the contract forbids ("wrong-input reuse is not an accepted fallback").
`refutation_or_invalidation`: refuted only if (a) SDK/plugin contents provably never affect output — TEST disproves (a) for SDK headers; plugin non-influence is unevidenced — or (b) those inputs are provably pinned by compiler bytes — CONFIG disproves the pinning.

## Minimum correction (to this PR)

Keep the compiler digest (correct for its axis), then restore the oracle for the remaining declared axes using the two mechanisms ARCHITECTURE_INTENT already authorizes:

1. **Resolvable inputs → include**: add resolved SDK header digests and loaded-plugin digests to the key wherever the environment/search path lets the tool resolve them.
2. **Unresolvable inputs → decline the hit**: where the tool cannot enumerate an input (e.g., per-target plugin set absent from config), conservatively miss (bypass reuse). Slower correct build is an accepted fallback by constraint; plugin enumeration absence is NEEDS_EVIDENCE but does not gate the fix — branch 2 covers it regardless.

No wider change: no toolchain-wide hashing mandate, no rewrite; a conservative-miss-only patch would also be acceptable (smaller but less useful), the above is the smallest patch that both preserves reuse gains and protects the property.

**Post-fix check**: compare claimed guarantee to mechanism — digesting resolved SDK/plugin inputs establishes input equality only for inputs the tool actually resolves; anything outside resolution (undiscovered search-path entries) remains unprotected and must fall into the decline branch, not be assumed equal. Do not promote the plugin-set assumption to CONFIRMED without enumeration evidence.
