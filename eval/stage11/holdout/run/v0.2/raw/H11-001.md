## Decision rationale

**Protected property (S1, AX-001).** Accepted PRODUCT_INTENT: every *accepted* survey finishes classification before its observation window closes, else it must be *rejected before responsibility is accepted*. This is a deadline-completion property that structurally **is** an admission obligation. Constraint: no permanent fleet approved; production arrival schedules and per-collection limits unset; the programme may change workload/windows at will (ARCHITECTURE_INTENT — this makes any static sizing fragile and makes the *structure*, not the fleet number, the thing that protects the promise). AX-003: none applicable — no regulatory/security non-negotiable is in scope. Scope excluded per constraints: model scientific accuracy.

**Evidence baseline (S2).**

KNOWLEDGE_DRIFT: **none** — a bare USER_ASSERTION vs project evidence is ordinary verification, not an accepted-intent conflict.

**Why the equipment request fails on mechanism, not on caution (S3–S4).** Mean GPU utilization answers "how busy was the pilot fleet," not "will accepted work finish before its window closes." Utilization headroom protects no deadline: clustered arrivals can miss every window at 61% mean busy, and a governed pipeline can be deadline-safe near saturation. Worse, the 61% came from hand-selected collections with the distribution unrecorded — it is not an estimator of production load at all (no tail, no variance, selection bias, and candidate hardware ≠ production fleet). And "no further measurements are needed" is contradicted by the same summary's admitted gaps plus CODE (schedules/limits unset): projected completion cannot be computed from any supplied input. GC-003 (exploration) does not rescue this — it excuses missing *modular boundaries*, not a biased statistic used as capacity proof. No derived throughput number is honestly computable from the given evidence; the missing inputs are named below.

**Min-sufficient structure (S5).** Property-derived, not pattern-derived:

1. **Admission gate at submission** (T-006): caller submits collection reference + declared size + window close; accept only if queued-ahead work + own service-time estimate (measured distribution + margin) ≤ window close − margin; otherwise **explicit reject** before responsibility transfers. The product contract literally specifies this mechanism.
2. **Bounded accepted work** (MP-003/FP-003): the queue contains only admitted surveys; each carries a propagated end-to-end deadline (T-003 deadline semantics) into per-tile waits; deadline expiry fails *that survey* rather than stalling the fleet; each accepted survey has one accountable owner until manifest or recorded deadline failure (MP-001).
3. **Minimal measurement, from day one**: per-collection service times, preprocessing time, sizes, arrival timestamps — exactly the runtime admission estimator's inputs (RUNTIME), not a telemetry stack (AX-004).

Non-prescriptions: no mandate for microservices, a queue product, Kubernetes, process isolation, or a degradation tier. A single supervised worker pool over the fleet with the gate in the submission path is a compliant form (GC-004: indefinite service lifetime, bounded per-work). Placement of the gate (submitter gateway vs service entry) is taste among compliant forms (GC-015).

**Alternatives.** (a) Queue-then-cancel-at-window-close: rejected — silently converts an accept-or-reject contract into best-effort (AX-002). (b) Static worst-case fleet sizing without admission: needs the *same* missing measurements, costs more, and breaks when the programme changes workload/windows. (c) Preferred: admission-gated structure now + **provisional, reversible** fleet capacity; permanent sizing decided by the owner once production distributions exist. With the admission structure in place, fleet size sets the *acceptance rate*, never the promise — which is what makes the structure the minimum correction and the fleet number an efficiency trade-off.

**Equipment request adjudication.** Not approvable as evidenced. Approval path: record per-collection service-time distribution + preprocessing overhead + expected arrival schedule (or stated bounds) on representative (not hand-selected) collections on production-representative hardware; compute worst-case projected completion vs windows with margin; then the owner trades acceptance-rate vs fleet cost.
