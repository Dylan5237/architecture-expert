user_request: Review the cache-key patch. The maintainer says hashing the compiler executable fixes reuse across
  toolchain updates and completes the declared build-input requirement.
project_evidence:
  product_intent: 'Accepted build contract: a cached result may be reused only when all declared inputs that affect
    the output are equal. SDK headers and loaded build plugins are declared inputs. Bypassing reuse is allowed when
    the tool cannot establish equality.'
  code: Current key includes source digest and flags. The patch adds the compiler-executable digest. The compiler
    also opens SDK headers from an environment-selected directory and loads plugins through a configured search
    path. Those paths/digests are not added to the key.
  test: A fixture holds compiler bytes, sources and flags fixed, changes the declared SDK header contents, and produces
    different executable bytes. With the patched cache key, it reuses the first executable.
  config: The SDK directory is selected independently of compiler installation. Plugin search paths are configurable.
    This packet contains no enumeration of which plugins are loaded for each target.
  architecture_intent: Compiler, SDK and plugin revisions have separate release schedules. The cache tool is allowed
    to record resolved input digests or conservatively decline a hit.
  user_assertion: The maintainer assumes that equal compiler bytes imply equal SDK and plugin inputs in every developer
    environment.
constraints:
- The proposed patch is scoped to cache reuse, not compiler replacement.
- A slower correct build is an accepted fallback; wrong-input reuse is not.
