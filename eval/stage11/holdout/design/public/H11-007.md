id: H11-007
title: An attachment access proposal
task_object: existing mobile expense-attachment download path and a proposed access guard
requested_mode: ARCH_REVIEW
user_request: Review whether adding authorization before issuing an attachment link completes the access-removal
  requirement for our expense app.
project_evidence:
  product_intent: 'Accepted access policy: after a manager removes a user from an expense record, every later download
    must be refused, including downloads initiated with a link obtained before removal. No grace period is accepted.'
  code: The API gives the mobile client a signed storage URL. The proposed guard checks membership before giving
    out a URL. The storage endpoint accepts any still-valid signed URL without consulting record membership.
  test: A client obtains a URL, the manager removes its membership, and the client fetches bytes directly from storage
    successfully with that URL. The proposal correctly refuses a subsequent request for a new URL.
  config: The storage URL remains valid until its signed expiration. Record membership changes do not invalidate
    that signature or object address.
  architecture_intent: Access removal is owned by the expense product/security owners. The design allows local changes
    to the download path but does not authorize delayed removal.
  user_assertion: The app lead says checking membership at link issuance closes every download path.
constraints:
- Existing issued URLs are part of the supported download flow.
- Attachments must remain downloadable to users who still have membership.
notes_for_runner: Fresh context. Use the frozen SUT and this case payload.
