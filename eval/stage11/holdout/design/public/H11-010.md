id: H11-010
title: An atlas snapshot client
task_object: existing immutable-map snapshot download client
requested_mode: ARCH_REVIEW
user_request: Review the client after an auditor objects to its persistent cache and asynchronous downloads, saying
  they necessarily display stale map data.
project_evidence:
  product_intent: 'Accepted atlas behavior: a view represents the selected published atlas revision, not the latest
    unpublished edits. Every tile in that view must belong to its selected manifest.'
  architecture_intent: Published manifests and their content-addressed tiles are immutable. A new revision is a
    new manifest address. Selecting a revision starts a new view object; existing views remain bound to the selected
    revision.
  code: Cache entries are keyed by tile content digest and verified against that digest on read. A view captures
    a manifest value before issuing downloads. Completion attaches a tile only if its digest is in that captured
    manifest. No mutable latest-tile key is used.
  config: Each view has a finite tile set and a bounded download budget. Cache eviction may discard entries; misses
    retrieve the same addressed tile. The publisher retains every selectable revision under the stated reader contract.
  test: Tests deliver old-view downloads after a new revision is selected, evict entries between reads, and reorder
    completions. A view remains composed only of its captured manifest tiles.
  user_assertion: The auditor equates an old cache entry with a violated freshness requirement and recommends removing
    cache and async delivery.
constraints:
- The reviewed view is tied to an explicitly selected published revision.
- Unpublished editing and publisher storage economics are outside this client review.
notes_for_runner: Fresh context. Use the frozen SUT and this case payload.
