# T-009 Functional / Quality Degradation

## Intent
Under pressure, deliberately reduce function, quality, or cost so remaining work stays within a governed boundary.

## Mechanism
Shed optional features, reduce fidelity, disable expensive paths — while still serving a defined core.

## Applies When
Overload or dependency failure where partial service is preferable to collapse.

## Does Not Solve
Entry control (T-006), upstream signaling (T-007), or dropping requests (T-008). Coupled fallback that shares the failing bottleneck is FP-005, not this tactic.

## Failure Patterns Mitigated
FP-010 (keeps a boundary by reducing demand). Not an alias of isolation (T-010).

## Principle Links
MP-009. Constitution does **not** require degradation together with admission.

## Trade-offs
Product-visible quality loss; must be an explicit policy.

## GOOD CASE / Misuse Boundary
Path-level control without in-service degradation code can still satisfy MP-009 (GC-015).

## Evidence / Gaps
SRE/Release It lineage; not mandated for every shape.
