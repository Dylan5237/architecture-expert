# FP-001 Unowned Runtime Work

## Failure Signature

A runtime entity (task/worker/timer/connection/async result) or mutable state cannot answer who creates, mutates, stops, and cleans it; after fault or context switch it leaks, orphans, or overwrites newer state.

## Causal Mechanism

Recovery and change need a locatable adjudicator. Missing ownership leaves cleanup/cancellation unassigned, so work outlives its context (S-084..086; S-062; S-091).

## Preconditions / Trigger

Concurrent or async work, timers, side-effecting resources, or mutable state; crash, cancellation, or owner replacement.

## Amplification Path

Orphaned workers keep mutating; stale completions overwrite; leaked handles exhaust capacity (then MP-003).

## Observable Evidence

Ownerless processes/tasks after parent exit; timers firing in a superseded context; write from a cancelled request landing after a newer owner.

## False Positives / GOOD CASES

- GC-001 OTP supervised daemon: supervision *is* ownership; indefinite lifetime is not ownerlessness.
- GC-002 GC reclamation: heap collection is not semantic task/session ownership.

## Consequences

Leaks, orphan work, stale overwrite, undiagnosable lifecycle.

## Mitigation Tactics

T-001 Supervised / Structured Lifecycle; T-002 Cancellation Propagation.

## Trade-offs / Scope

Explicit ownership has ceremony cost on short scripts. Java StructuredTaskScope realization remains RQ3-002.

## Principle Links

MP-001. If the overwrite comes from an assumed ordering/cancellation guarantee the model does not provide, diagnose FP-012 / MP-010 (D-02), not only this FP.

## Evidence / Gaps

Structured-concurrency lineage S-084..086; OTP S-114 scoped; accidents S-091/S-062. RQ3-002 open.
