# FP-011 Retry Amplification

## Failure Signature

Failed or slow calls are retried (often synchronized) so offered load grows while useful capacity shrinks, producing a retry storm.

## Causal Mechanism

Retry without bound, jitter, or an upstream capacity boundary multiplies arrivals into an already overloaded system (S-052 official antipattern; S-048/S-050).

## Preconditions / Trigger

Timeouts/errors on a shared dependency plus client or mesh retry.

## Amplification Path

Timeout → retry → more occupancy → more timeout. Distinct from merely missing an overload boundary (FP-010) and from unbounded per-work retry count as a bound issue (FP-003).

## Observable Evidence

Retry rate dominates original request rate; synchronized retry waves; recovery traffic without a boundary.

## False Positives / GOOD CASES

Bounded, jittered retry behind an effective path boundary (GC-015) is not this FP. Idempotent processing (T-015) does not by itself stop storms.

## Consequences

Self-inflicted overload; prolonged outage.

## Mitigation Tactics

T-005 with bounds/jitter; T-006/T-007/T-008 on the path. T-015 is complementary under at-least-once delivery, not a substitute.

## Trade-offs / Scope

Retry remains a valid tactic for transient faults when bounded.

## Principle Links

MP-009 primarily; per-work retry bound also MP-003. Keep the two diagnoses separable (D-04).

## Evidence / Gaps

S-052 is the named antipattern source. No extra universality claimed.
