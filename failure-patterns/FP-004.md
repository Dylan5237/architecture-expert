# FP-004 Shared-Resource Failure Cascade

## Failure Signature

A fault in one subunit propagates through shared resources or dependencies until blast radius exceeds the designed failure domain.

## Causal Mechanism

Failure travels along shared dependency/resource graphs; isolation cuts that graph (S-047, S-050, S-061).

## Preconditions / Trigger

Shared bottleneck, multi-tenant path, or high-cost failure path.

## Amplification Path

Retry, timeout coupling, and shared-thread/connection pools expand the affected set.

## Observable Evidence

One dependency/resource outage takes unrelated functions with it; impact crosses the intended partition.

## False Positives / GOOD CASES

- GC-005 SQLite single-process economics: no process boundary required.
- GC-006 Arrakis: credit only the I/O protection dimension actually constrained.

## Consequences

Availability loss beyond the failing duty.

## Mitigation Tactics

T-010 Scoped Failure-Domain Isolation. Not a generic process split.

## Trade-offs / Scope

Graded/economic. No admitted universal blast-radius metric (RQ5-001 / D-10). failure domain ≠ blast radius.

## Principle Links

MP-004. Low-privilege services can still cascade via shared resources (D-05 vs MP-005).

## Evidence / Gaps

Incident/SRE concentration; RQ5-001 open. Do not inherit MP-005 evidence.
