# FP-012 Assumed-vs-Provided Guarantee Mismatch

## Failure Signature

Correctness depends on a timing/order/interrupt/cancellation/clock guarantee that the chosen execution model, primitive, or contract does not actually provide. Predicate: assumed guarantee ≠ model-provided guarantee.

## Causal Mechanism

Scheduler, delay, reordering, cancellation, or clock perturbation exercises behavior outside the assumed model (Lamport partial order S-025; FLP scoped S-030; structured-concurrency mismatch S-084..086).

## Preconditions / Trigger

Concurrency, asynchrony, distribution, or cancellation propagation.

## Amplification Path

A rare perturbation turns an implicit assumption into a concrete wrong result (including stale async completion when the model did not provide the assumed order).

## Observable Evidence

Heisenbugs under load/preemption; cancelled work completing later; clock/timeout reasoning that the runtime does not guarantee.

## False Positives / GOOD CASES

- GC-016 model-provided per-pair actor order, non-preemptive event-loop segments, or concrete DBMS isolation actually promised — must not be flagged.

## Consequences

Incorrect results under perturbation.

## Mitigation Tactics

No named tactic file. Choose/enforce a primitive that provides the guarantee, or remove the dependency.

## Trade-offs / Scope

Formal results are theorem-scoped. Mechanical determination of “does the model provide X?” is RQ5-002. ANSI isolation names are not actual semantics (RQ5-005).

## Principle Links

MP-010. If the stale write is missing cleanup ownership rather than a false ordering assumption, use FP-001 (D-02). Distinct from MP-008 conflict semantics (D-09).

## Evidence / Gaps

RQ5-002, RQ5-005. Single-process operationalization thinner than distributed/concurrency theory.
