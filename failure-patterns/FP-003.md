# FP-003 Unbounded Per-Work Dimension

## Failure Signature

A per-work dimension (execution/wait/retention time, retry, queue, concurrency, memory, fan-out) has no effective bound or governed policy and exhausts shared capacity under load or fault.

## Causal Mechanism

L=λW: with finite capacity, unbounded work becomes backlog and cascading timeout (S-072/S-073). Unbounded buffers break backpressure (S-090). Event-loop blocking is a time-bound failure (S-088).

## Preconditions / Trigger

Shared resources, external input, async work, or cross-boundary calls.

## Amplification Path

Retries, fan-out, and retained work multiply occupancy until adjacent paths starve.

## Observable Evidence

Growing queues, thread/task explosion, memory without a budget, waits with no timeout/deadline/cancellation.

## False Positives / GOOD CASES

- GC-004 indefinite service/stream lifetime with bounded per-work dimensions.
- GC-002 runtime soft memory budget.

## Consequences

Resource exhaustion, latency collapse, availability loss.

## Mitigation Tactics

T-003, T-004, T-005 (bounded retry). Overload *policy* is FP-010 / MP-009, not this FP (D-04).

## Trade-offs / Scope

Little's Law does not prove every listed dimension. Implied bounds (input-limited batch) are legal.

## Principle Links

MP-003. Owned-but-unbounded vs bounded-but-unowned: D-07 with MP-001.

## Evidence / Gaps

Queueing theory plus incidents/platform contracts, all dimension-specific.
