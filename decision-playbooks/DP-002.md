# DP-002 Architecture Review

## Trigger

Use when the object is an **existing system, subsystem, or path**, judged against required properties. No required incident; no required diff. Overlays specialize the first domain (concurrency, overload, reliability, …) without changing this procedure.

Typical asks: “review this architecture”, “is this sound?”, “health check of X path”.

## Do Not Use When

- Nothing exists yet to audit → [DP-001](DP-001.md).
- The question is “is this PR/migration safe?” and the delta is the object → [DP-003](DP-003.md).
- The object is an ADR’s rationale/alternatives → [DP-004](DP-004.md).
- The user is debugging a live failure → [DP-005](DP-005.md); return here only after the mechanism is attributed and they want a broader review.

## Goal

Decide whether the current architecture protects the required properties; if not, name the mechanism and the minimum correction. Correct result may be `NO_DEFECT`.

## Minimum Inputs

- What system/path is in scope.
- Required properties (from PRODUCT_INTENT or stated review charter).
- Access to current-behavior evidence, or an explicit `NEEDS_EVIDENCE` plan to get it.

## Evidence Baseline

Current behavior: CODE, CONFIG, TEST, RUNTIME first.

Intended behavior: PRODUCT_INTENT.

Architecture intent: ARCHITECTURE_INTENT, HISTORY.

GENERIC_KNOWLEDGE last for project-specific claims. If these disagree → `KNOWLEDGE_DRIFT`.

A review with only a diagram and no CODE/RUNTIME/TEST should usually stop at `NEEDS_EVIDENCE` rather than BLOCKER, unless the diagram itself asserts an impossible guarantee.

## Conditional Reasoning Path

1. Confirm this DP; pick overlay from the index table if the ask names a family.
2. Intent & properties. AX-001: no property-free “this looks messy”.
3. Evidence baseline for *current* behavior vs *intended* behavior. Record drift.
4. Activate only dimensions that the overlay or observed shape justifies. For overlay “runtime/stale async”, activate Q-OWN **and** Q-XCN together (D-02). For overlay “overload”, activate Q-OVL and add Q-RES only if a per-work dimension may be unbounded.
5. For each activated suspicion: identify candidate FP; **load matching GC**; ask whether the mechanism is actually present.
6. Classify with the verdict table. BLOCKER needs evidence + mechanism + failure mode + impact.
7. Minimum correction for confirmed defects. Stop.

Do not walk all ten MPs. Do not flag “not microservices” or “no circuit breaker file”.

## Question Sets

Always: Q-INT, Q-EVD, Q-PRP, Q-UNK.

Overlay-selected: see index overlay table.

Before any defect: relevant GC questions implied by Q-VAL / the GC row, not a second question bank.

## Stop Conditions

Index stop 1–6, plus:

- `NO_DEFECT` after GC match or absent mechanism is a successful stop.
- Stop after one supported BLOCKER/MUST_FIX plus min correction if further findings cannot change that decision (note others as `NON_BLOCKING_IMPROVEMENT` or later work).

## Escalation Conditions

Index list. Review-specific: contested PRODUCT_INTENT vs CODE that owners must pick (`KNOWLEDGE_DRIFT`); applicable AX-003 interpretation; trust policy.

Do not escalate “I prefer hexagonal layers”.

## Output Contract

Index shared schema. `findings` are defects, risks, `NO_DEFECT`, or `NEEDS_EVIDENCE`. Include `gc_checked` whenever a suspicious surface was considered.

## Anti-overengineering guard

Recommend the smallest change that breaks the named mechanism. Do not prescribe a platform, a rewrite, or a missing buzzword tactic (circuit breaker, strangler, event sourcing, hedged requests) unless that exact mechanism is the min correction and is not already covered by an existing T-*.

## Common category mistakes

- Keyword matching (“retry” → always FP-011) without mechanism.
- Punishing GC-compliant forms (OTP indefinite lifetime, SQLite single-process, path-level admission, coarse trust with no relevant boundary, proof-scoped seL4).
- Collapsing D-02 (ownership vs assumed guarantee) into one finding.
- Using blast radius as if it were a failure domain (RQ5-001).
- Treating P-006 spread as a violation (GC-007).
- Reviewing taste and calling it BLOCKER.
