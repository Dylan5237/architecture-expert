# P-013 Execution-Model-Honest Correctness

## Statement
**Correctness must not depend on timing, ordering, interruption, cancellation, or clock guarantees that the actual execution model does not provide.** 正确性所依赖的时序、顺序、中断、取消或时钟保证，必须由实际的 primitive / contract / coordination semantics 强制提供；文档化或口头声明不构成保证。

## Mechanism
隐式依赖不存在的保证，在 scheduler perturbation、延迟、重排序、取消或时钟行为下失效：Lamport（S-025）——分布式中「先后」只有偏序，全局时序是构造物而非物理事实；FLP（S-030，注意 RQ2-005 限定：完全异步+确定性下共识无保证终止）与 DLS（S-031）——活性依赖执行模型实际提供的同步程度。协作式调度（V-007-C）下「这段代码之间不会被打断」依赖挂起点语义；取消语义（V-008-C：structured-scope 取消使 context 切换后旧工作失效，S-084..086）是执行模型实际提供的 primitive 的例子。Pathfinder（S-091）：时序窗口只在真实负载数据率下暴露——测试中未出现 ≠ 保证存在。

## Operationalization（非因果机制部分）
「显式声明时间/时序假设」是评审与验证的辅助手段（review aid）：把依赖的保证写成可检查清单，逐条核对执行模型是否实际提供。它是发现本原则违反的技术，不是本原则本身。

## Protects
correctness（时序相关的正确性）。

## Applies When
并发、异步、分布式、取消传播存在的系统。

## Does Not Necessarily Apply When
严格单线程顺序执行的批处理；无共享状态的纯 pipeline。

## Failure Patterns Explained
stale async overwrite；race condition；时序窗口故障（S-091）；「测试通过但生产偶发」类不可复现缺陷；取消未传播导致的僵尸工作。

## Trade-offs / Costs
用实际 primitive 强制保证（锁、全序化、版本/generation 防护）牺牲吞吐与简单性；保守串行化的性能代价。

## Distinguish From
- P-001（ownership 管归属；判别测试 D-02：stale overwrite 归因——归属明确但时序保证缺失 vs 时序保证齐备但清理归属悬空）；
- P-010（状态裁决语义；判别测试 D-09：全序化序列的重复投递 vs 权威齐备但时钟漂移破坏顺序）；
- linearizability（V-011-B）等一致性模型是可选的 enforce 手段，不是义务；
- idempotency（V-021-B）是缓解 tactic（按 OD4-3 记为 explicit delivery semantics 下的 mechanism/tactic/contract property，非独立原则）。

## Evidence
- S-025（theoretical，Lamport）；S-030/S-031（theoretical，FLP/DLS）；S-023（综合）；S-084..086（normative，平台取消语义——同一概念谱系的平台实现，按 CA4-10 计为一族加平台佐证）；S-091（empirical，时序事故）。
- 独立家族：分布式理论 + 平台契约（单谱系） + 航天事故。单进程形态的理论锚较薄（自认）。

## Cross-System-Shape Check
分布式（S-025/030/031）、并发运行时（S-084..086）、嵌入式 RTOS（S-091）、后端异步（S-023）。成立。

## Counterexample / Falsification Plan
①寻找「隐式依赖但长期正确」的成熟系统（actor 模型的串行邮箱语义是否使时序保证隐式但由模型实际提供——S-081/083；若如此则恰支持本候选：保证来自模型而非文档）；②检验「执行模型提供什么保证」的可判定性（评审时能否机械判定）；③D-02/D-09 边界判别（与 P-001/P-010）。
