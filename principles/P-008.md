# P-008 Contract Preservation（契约保持）

## Statement
对已有交互方的 contract（V-012-B：接口+行为语义+非功能承诺的全体）变更必须保持显式的兼容性（V-012-D）方向与迁移路径；破坏兼容的变更是一个显式的、带成本声明的决策，而不是重构的副产品。compatibility 方向必须带 reader/writer（或 producer/consumer）视角（V-013-A/B）。

## Mechanism
契约是跨边界协作的唯一稳定点；破坏契约 = 把变更成本强转嫁给所有交互方（协调爆炸或静默故障）。兼容性规则（S-044：BACKWARD/FORWARD/FULL+TRANSITIVE，注册时强制检查）把「能否变更」变成可机检的谓词；schema 保留字段/unknown-field 转发（S-045）是兼容的机制实现。数据迁移路径（expand/contract 家族）使破坏性变更以并存期完成而非切换瞬间完成。

## Protects
compatibility（V-012-D）、evolvability（变更可演进不冻结）、correctness（无静默语义漂移）。

## Applies When
存在独立演进节奏的多方交互：公开 API、持久化 schema、跨团队接口、消息契约。

## Does Not Necessarily Apply When
单一所有权内的内部接口（同库同发布节奏——内部接口严格兼容是过度仪式，S-044 的机制成本不付值）；原型期。

## Failure Patterns Explained
schema migration incompatibility； backward-compatibility break（方向混淆导致的静默破坏）；部署顺序死锁（新旧互等）；事件契约漂移。

## Trade-offs / Costs
并存期的双栈维护；兼容约束限制设计空间；兼容性检查工具链成本。

## Distinguish From
- evolvability（V-013-E 属性）——本候选是保护它的机制主张之一，二者 Stage 5 判别是否合并；
- expand-contract（V-021-G）：tactic 且当前 NEEDS_EVIDENCE（RQ3-006），本候选不以它为唯一机制；
- H5a/P-005（决策程序）——契约破坏的不可逆性高，P-005 管「投入多少论证」，本候选管「不得静默破坏」。

## Evidence
- S-044/S-045（normative，兼容性方向与 schema 机制——事实标准）；
- S-039（theoretical/normative，REST 的 uniform interface 演化约束）；
- S-042（normative，gRPC deadline/契约语义——平台 normative）；
- S-037/S-038（theoretical/empirical，Saga/Helland：跨实体一致性的补偿路径）。
- 独立家族：规范级 + 学位论文 + 平台文档 + 分布式数据库谱系。注意契约兼容性证据集中于数据/接口层；行为语义兼容的实证较薄。

## Cross-System-Shape Check
后端 API（S-042）、DB schema（S-044）、Desktop/嵌入式（ABI 兼容——Win32 材料被 RQ2-013 CH-S-04 拒绝，该形态实证缺席，标注不声称覆盖）、Local-first（S-107 离线副本的格式演进）。

## Counterexample / Falsification Plan
①内部单所有权接口过度兼容的伤害案例（并行演进成本）；②寻找「破坏兼容但无迁移路径也成功」的反例及其条件（用户量极小？）；③行为语义兼容（非 schema）是否可机检——若不可，本候选的可执行面收窄。
