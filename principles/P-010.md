# P-010 Authoritative State（状态权威）

## Statement
每类状态（V-009-A）必须有两个显式声明的、正交但交互的维度：

1. **write / state authority**（V-003-D）：谁有权决定或修改权威状态（source of truth，V-009-B 的写侧归属）；
2. **conflict / consistency semantics**：并发或复制的读写在冲突时如何调和、提供什么 consistency 保证（V-010-A：引用时必须带 ACID / replica / cache 等义项后缀）。

权威不清，**或**冲突/一致性语义未定义，都会使并发与故障下的状态结果不可判定——以分歧、丢失更新或陈旧覆盖的形式失效。single-writer 不是本原则的必需条件（多写 + 显式合并语义是合法形态，留 Stage 5 D-14 检验收窄边界）。

## Mechanism
并发写下无裁决规则 → 冲突无定义解（lost update / write skew——S-034 的 SI 分析）；缓存副本与权威漂移（cache consistency，V-010-A 义项四）；事件溯源把 SoT 移到 append-only log（S-040/S-046），状态成为可重建投影——权威显式化的一种形态；Helland（S-038）：跨实体无事务权威，必须用幂等（V-021-B）与补偿显式管理一致性敞口。注意两个维度的正交性：单写权威可以配弱副本一致性语义，多写也可以配显式合并语义——一个维度的选择不决定另一个维度的强度。

## Protects
correctness（状态语义可推理）、reliability（故障后权威可恢复）。

## Applies When
存在可变状态 + （并发写 或 多副本 或 缓存层）的系统。

## Does Not Necessarily Apply When
纯派生数据（可重建、无裁决需要）；只读视图；真正的 append-only 无冲突域。

## Failure Patterns Explained
cache consistency drift；stale async overwrite；write skew（S-034）；split brain 后的双权威（S-060）；迁移期双写不一致。

## Trade-offs / Costs
强裁决语义的可扩展性/延迟代价（PACELC 的 else 分支，S-028）；event sourcing 的回放与 schema 演进成本；合并语义（若采用多写）的设计与验证成本。

## Distinguish From
- 「用 event sourcing/CQRS」（tactic，S-040/S-041，且 CQRS 被警告过度套用）；
- P-001（ownership 管运行时实体与状态的归属程序，本候选管状态的裁决与冲突语义——判别测试 D-06：ownership 清晰但一致性义项未声明的系统）；
- P-013（时序保证）：判别测试 D-09（全序化序列的重复投递 vs 权威齐备但时钟漂移）。

## Evidence

- S-034（theoretical，隔离级别批评）；S-036（theoretical/empirical，HAT）；
- S-040/S-046（heuristic/empirical，ES 与 Log 谱系）；
- S-038（empirical/heuristic，Helland）；S-107（theoretical，local-first 形态：主副本在用户设备的权威内化）。

## Cross-System-Shape Check
