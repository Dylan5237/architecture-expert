# P-010 Authoritative State（状态权威）

## Statement
每类状态（V-009-A）必须有显式的权威所在（source of truth，V-009-B）与写权归属（状态 authority，V-003-D），并声明其 consistency 语义的具体义项（V-010：ACID 不变量 / replica 光谱 / cache 漂移——引用时必须后缀）；多个可写副本而无裁决规则的状态，在并发与故障下以分歧、丢失更新或陈旧覆盖的形式失效。

## Mechanism
并发写下无裁决者 → 冲突无定义解（lost update / write skew——S-034 的 SI 分析）；缓存副本与权威漂移（cache consistency，V-010-A 义项四）；事件溯源把 SoT 移到 append-only log（S-040/S-046），状态成为可重建投影——权威显式化；Helland（S-038）：跨实体无事务权威，必须用幂等（V-021-B）与补偿显式管理一致性敞口。复制一致性光谱（strong/eventual）的选择即权威强度的选择（S-023）。

## Protects
correctness（状态语义可推理）、reliability（故障后权威可恢复）。

## Applies When
存在可变状态 + （并发写 或 多副本 或 缓存层）的系统。

## Does Not Necessarily Apply When
纯派生数据（可重建、无裁决需要）；只读视图；真正的 append-only 无冲突域。

## Failure Patterns Explained
cache consistency drift；stale async overwrite；write skew（S-034）；split brain 后的双权威（S-060）；迁移期双写不一致。

## Trade-offs / Costs
单权威的可扩展性/延迟代价（PACELC 的 else 分支，S-028）；event sourcing 的回放与 schema 演进成本；强一致的可用性代价。

## Distinguish From
- 「用 event sourcing/CQRS」（tactic，S-040/S-041，且 CQRS 被警告过度套用）；
- P-001（ownership 管运行时实体与状态的归属程序，本候选管状态的裁决语义——判别测试： ownership 清晰但一致性语义未声明的系统）；
- consistency 四义项（V-010）：本候选使用其义项一/三/四时必须分别限定。

## Evidence
- S-023（theoretical/empirical 综合教材）；
- S-034（theoretical，隔离级别批评）；S-036（theoretical/empirical，HAT）；
- S-040/S-046（heuristic/empirical，ES 与 Log 谱系）；
- S-038（empirical/heuristic，Helland）；S-107（theoretical，local-first 形态：主副本在用户设备的权威内化）。
- 独立家族：数据库理论 + 工业日志哲学 + 分布式实践 + local-first。注意 RQ2-004：任何 CAP 引用须带原子寄存器语义限定。

## Cross-System-Shape Check
DB-heavy（S-034）、分布式（S-023/038）、local-first（S-107）、Mobile（S-105 的 SSOT vendor-scoped owner 语义——仅平台 normative）。成立。

## Counterexample / Falsification Plan
①寻找「多可写副本无裁决但长期正确」的系统（CRDT 是无裁决问题的另一种解法——S-107 谱系；若 CRDT 成立则本候选需收窄为「无 CRDT 类合并语义时」）；②event sourcing 的失败案例（回放成本爆炸）；③「显式声明 consistency 义项」的可操作性——团队语言层面做不到时本候选是否退化为文档仪式。
