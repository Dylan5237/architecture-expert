# P-009 Trust Minimization

## Statement
每个组件应只被信任到其职责所需的最小程度：权限最小化（least privilege）、信任边界（V-016-A）显式、不可信输入在边界处校验；信任范围超出职责的部分，就是攻击面与故障面的无偿扩张。

## Mechanism
Saltzer & Schroeder（S-092）：攻击者能造成的损害 ≤ 被攻破组件持有的权限；least privilege 直接上限化单点攻破的损失。零信任（S-093）否定网络位置即信任——信任必须由显式验证产生。威胁建模（S-096）以 trust boundary 为建模原语：边界两侧的数据流需要不同的校验与授权（V-016-D）语义。Agent 形态（S-110）：prompt injection 把不可信内容转化为 agent 动作，信任边界从「输入校验」扩展到「输出动作的执行权」。

## Protects
security（攻击面上限）、reliability（不可信输入引发的故障面收窄）。

## Applies When
存在不可信输入、多权限级别、外部集成、或 agent 执行动作的系统。

## Does Not Necessarily Apply When
完全封闭的单用户本地工具中，内部信任边界的 ceremony 可能不付值；但 supply chain（依赖）仍是不可信输入——豁免面比直觉窄。

## Failure Patterns Explained
注入类攻击（含 prompt injection，S-110）；权限过度导致的横向移动；secret 泄漏；过度信任的 fallback 被利用。

## Trade-offs / Costs
边界校验与授权的成本与延迟；过度细分权限的运维负担；「默认拒绝」对开发体验的摩擦。

## Distinguish From
- 具体安全 tactic（加密、沙箱、WAF——tactic 层）；
- P-004（failure isolation 管故障传播，本候选管信任/权限——机制不同但共享「权力≤职责」的深层结构，Stage 5 判别是否合并为更深层原则）；
- capability（V-016-C）：机制词条且当前 NEEDS_EVIDENCE（RQ3-004）。

## Evidence
- S-092（theoretical/normative，1975 八原则原始出处）；
- S-093（normative，NIST 标准）；
- S-096（normative，STRIDE 事实标准）；
- S-110（normative/empirical，OWASP GenAI——新兴，成熟度有限已标）；
- S-112（normative，platform-scoped：Electron 渲染进程最小权限的形态实例）。
- 独立家族：经典理论 + 政府标准 + 厂商方法论 + 社区标准 + 平台契约。历史最久、独立性最强的候选之一。

## Cross-System-Shape Check
企业分布式（S-093）、Web（S-094/095 背景）、Desktop（S-112）、Agent runtime（S-110）、Embedded（S-104 无 OS 保护时边界退化——形态限定）。成立。

## Counterexample / Falsification Plan
①寻找信任最小化成本明确超过风险收益的场景（内部工具、单机软件）——检验 graded 边界；②least privilege 在微服务扩散后的运维爆炸是否构成反例（机制成本反噬）；③与 P-004 合并判别：是否存在「故障权力大但信任权力小」或反之的真实系统对。
